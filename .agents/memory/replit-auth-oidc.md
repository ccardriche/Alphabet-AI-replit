## Schema decisions
- `users.id` is `text` (not uuid) — holds the Replit OIDC `sub` claim (a numeric string like "12345678")
- `student_profiles.userId` is also `text` (FK to users.id)
- Sessions stored in DB `sessions` table via custom `createSession`/`getSession` helpers in `artifacts/api-server/src/lib/auth.ts`
- Session cookie name: `sid`

**Why:** Replit OIDC `sub` is not UUID-shaped. Changing to text avoids hash/conversion complexity.

## Auth flow
1. `GET /api/login` → sets OIDC cookies (code_verifier, nonce, state, return_to) → redirects to Replit OIDC
2. `GET /api/callback` → exchanges code, upserts user in DB, creates session, sets `sid` cookie, redirects to returnTo
3. `authMiddleware` reads `sid` from cookie (or `Authorization: Bearer <sid>`), loads session, sets `req.user`
4. `GET /api/auth/user` → returns `{user: AuthUser | null}`
5. `GET /api/logout` → clears session, redirects to OIDC end_session_endpoint

## Frontend
- `@workspace/replit-auth-web` lib at `lib/replit-auth-web/src/`
- Provides `useAuth()` hook: fetches `/api/auth/user`, provides `login()` and `logout()`
- Vite alias required — see vite-workspace-libs.md
- `AuthUser` type comes from `@workspace/api-zod` (generated by Orval from OpenAPI `AuthUser` schema)

## Route protection pattern
- Routes check `req.isAuthenticated()` and return 401 if false
- Student routes look up student profile via `getStudentByUserId(req.user.id)`
- Teacher routes use `req.user.id` directly as teacherId

## openid-client
- Package: `openid-client` in `@workspace/api-server` dependencies
- OIDC config cached in module-level variable in `lib/auth.ts`
- Uses PKCE flow (S256)
