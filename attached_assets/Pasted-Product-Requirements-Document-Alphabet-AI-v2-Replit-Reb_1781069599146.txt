Product Requirements Document — Alphabet AI v2 (Replit Rebuild)
Working title: Alphabet AI — Adaptive K-12 ELA Mastery Platform Author: China Cardriche Status: Draft v1.1 Last updated: June 10, 2026 Target build environment: Replit (full-stack) — React + Vite frontend, Node/Express API, Supabase (Postgres + Auth + Storage + Realtime) Builds on: Alphabet AI — Product Design Reference (PDR) v1.0, June 2026 (the existing rebuild spec) Replaces: Alphabet AI Base44 app (6958a13f5cd77c4eabd5441c, 59 entities)

How to read this document. The PDR is the authoritative design reference for the current Base44 app and its 1:1 Replit port. This PRD sits on top of it: it carries the PDR's decisions forward verbatim where they hold, and specifies the substantial extensions that make the rebuild more comprehensive and aligned to IXL's skill-progression model. Sections marked [from PDR] restate the existing spec; sections marked [new / extends PDR] are the additions this rebuild introduces.


1. Executive summary
Alphabet AI is a Science-of-Reading, culturally-responsive ELA platform. The PDR already specifies a faithful Replit rebuild of the current Base44 app — same data model, same React stack, Supabase backend, a working 3-PL IRT placement engine, an 8-phase build plan, and six pilot rubrics.

This PRD pushes that rebuild three steps further, per the requested direction:

Full K-12 breadth at IXL granularity. The PDR already envisions an ELASkill catalog of ~2,000+ granular sub-skills. This PRD operationalizes that as an IXL-style, single-objective skill catalog — seeded directly from the 13 uploaded IXL skill plans (grades K-12), which already enumerate ~1,200 granular skill alignments.
Port and extend the data model into owned Postgres, layering a continuous SmartScore-style mastery score (0-100) on top of the PDR's discrete mastery_level.
A custom adaptive engine and content-authoring pipeline that go beyond the PDR's single-θ IRT — full computerized-adaptive testing (CAT), per-domain θ, spaced repetition, and AI-assisted item authoring at scale.

It also surfaces one decision that must be made before Phase 1: the PDR is built on Georgia's old GSE (ELAGSE…) standards, but the uploaded IXL plans target Georgia's 2025 K-12 ELA Standards (a new F/L/T strand architecture). See §5.


2. Product vision [from PDR]
Mission: give every K-12 student — especially those reading below grade level — a personalized, culturally responsive ELA experience grounded in the Science of Reading, standards-aligned, and powered by AI-adaptive instruction.

Pillars carried from the PDR:

Adaptive assessment — IRT placement routes K-12 in real time; diagnoses grade-equivalent reading level, identifies strand gaps, builds intervention plans.
Standards-first — every skill, question, and lesson maps to a specific standard code with a CCSS crosswalk; coverage tracked against Rubric 06 (≥80% priority standards).
Culturally responsive — student interests, cultural context, and home language drive all content generation; no generic passages.
Durable skills — tracks 10 America Succeeds durable-skill dimensions alongside academic standards.
Teacher visibility — real-time standards heatmaps, growth velocity, intervention flags, coverage rollups.
Three-mode work time — Whole-Class Framing → Individual Adaptive Practice → Group Discussion; uploaded books generate aligned lessons.

6. The skill progression model — IXL alignment [new / extends PDR]
The PDR already defines a granular ELASkill entity (~2,000+ records) with prerequisite/next chains and IRT parameters. This section makes that catalog IXL-aligned in three layers.
6.1 Layer 1 — Granular skill catalog
A Skill = one specific objective (e.g. "Does the word end with a consonant blend?", "Identify appositives and appositive phrases."). Fields extend the PDR's ELASkill:

skill_code (e.g. RF-PA-01 today → migrate to 2025-aligned codes), skill_name, description
standard_leaf_code (one 2025 substandard) + parent_gse_code + parent_ccss_code (crosswalk, kept from PDR)
domain/strand/substrand, grade_level, grade_band, sub_skill_order
prerequisite_skill_codes[], next_skill_codes[] (the DAG that powers intervention walking)
IRT params difficulty (b, -3..+3), discrimination (a, default 1.0), guessing (c, default 0.25) [from PDR]
sor_pillar (F-strand only), culturally_relevant_themes[], durable_skill_codes[], activity_types[], active

Seeding: ingest the 13 uploaded IXL plans as the catalog backbone (~1,200 skills already mapped to 2025 standards), then extend toward the ~2,000+ target.
6.2 Layer 2 — Continuous mastery scoring (SmartScore-style)
Add a live SmartScore (0-100) per (student, skill) alongside the PDR's discrete mastery_level:

Rises with correct answers, falls with errors; weighted by item difficulty, consistency, and volume.
80 = Proficient (matches the PDR's existing 80% advance threshold), 90 = Challenge Zone (harder items to confirm), 100 = Mastery.
Decay/refresh so stale mastery prompts light review (ties to spaced repetition, §8).

This makes the proficiency signal continuous and IXL-comparable while preserving the PDR's mastered/approaching/practicing/introduced labels as derived bands.
6.3 Layer 3 — Adaptive routing
Two behaviors, both extending the PDR's engine (§8): IRT diagnostic placement (start point in the catalog graph) and in-skill difficulty ramp (each skill opens with intro items and ramps in real time).

8. Adaptive engine [from PDR baseline + extensions]
8.1 Baseline (PDR — ship as-is in Phase 2)
3-Parameter Logistic IRT, Newton-Raphson θ update, theta→grade mapping, skill selector, and mastery computation are already specified as working code:

// 3-PL IRT
function irtProb(theta, a=1, b=0, c=0.25) {
  return c + (1 - c) / (1 + Math.exp(-a * (theta - b)));
}
// θ update (Newton-Raphson), bounded -3..+3
function updateTheta(prevTheta, correct, skill) {
  const { difficulty: b, discrimination: a = 1, guessing: c = 0.25 } = skill;
  const p = irtProb(prevTheta, a, b, c);
  const info = a**2 * (p-c)**2 * (1-p) / (p * (1-c)**2);
  const delta = info > 0 ? (correct ? 1 : -1) * ((p-c)/((1-c)*info)) : 0;
  return Math.max(-3, Math.min(3, prevTheta + delta));
}
// Stop: 20 questions OR SE < 0.5 after min 10
const shouldStop = (count, n) => count >= 20 || (count >= 10 && 1/Math.sqrt(n) < 0.5);

thetaToGrade maps θ (-3=K … +3=12th) linearly; selectNextSkill prioritizes needs_reteaching → approaching → practicing → introduced → not_started; computeMastery advances to mastered at ≥80% over ≥5 attempts.
8.2 Extensions (this rebuild)
Isolate the engine as a dedicated, unit-tested service (Node module or Python FastAPI) and upgrade per the PDR's own "Improvement Opportunities":

Full CAT with a pre-calibrated item bank (AdaptiveItem) and maximum-information item selection, replacing question-by-question LLM generation at test time (pre-generate + cache).
Multi-dimensional IRT — a separate θ per domain/strand, so placement reports per-strand strengths/gaps natively.
Tighter stopping (SE < 0.3) for diagnostic precision; RIT-equivalent, Lexile, and grade-equivalent outputs.
SmartScore layer (§6.2) — translate item outcomes into the 0-100 per-skill score with Challenge-Zone gating at 90.
Spaced repetition (SM-2) for review scheduling and SmartScore decay.
engine_version stamped on every result for reproducibility/audit (supports Rubric 02).


9. Feature specifications [from PDR]
F1 — Adaptive Placement (IRT). 3-PL; start θ=0 (6th), Newton-Raphson update; stop at 20 Qs or SE<0.5 after ≥10; θ→grade; LLM-generated questions personalized by interests; outputs diagnosed_grade_level, placement_pathway, strand strengths/gaps, seeds StandardMastery; gates the dashboard until pre_assessment_completed.
F2 — Daily Adaptive Practice (5 activities). Listen & Repeat → See & Tap → Say It → Write It → Read It; selects next unlocked skill by priority; LLM prompt includes skill, standard, interests, cultural_context, home_language; mastery at 80% over ≥5; 3 consecutive errors → reteach; XP 10/correct + bonuses; ElevenLabs TTS on all text.
F3 — Work Time (3-mode rotation). Whole-Class Framing (10 min, ContentLibrary + timer) → Individual Practice (20 min, DailyPractice) → Group Discussion (15 min, LLM-generated prompts/roles); order on TeacherClass.work_time_rotation.
F4 — Book Upload & Lesson Generator. PDF/EPUB or pasted text → select grade/domain/standard → generates framing lesson, 7 tiered discussion questions, 3 writing prompts, 15-word vocab list → saved to ContentLibrary; feeds F3 framing.
F5 — Intervention Pathway (3 phases). Detects grade gap (enrolled − diagnosed); Phase 1 Foundation Reset → Phase 2 Gap Acceleration → Phase 3 On-Grade Growth; each skill card = mastery bar + Practice launch.
F6 — ELA Skill Tree (IXL-style). K-12 grade selector loads ELASkill by grade, grouped by domain with color coding + mastery heatmap; expand for standard code, CCSS crosswalk, cultural themes, durable-skill links, next unlocks; search by name/code/domain.
F7 — Teacher Roster (standards heatmap). Student × enrolled/diagnosed grade × avg score × growth velocity × domain heatmap; filters All/Intervention/On Track/Not Tested; detail panel with full heatmap, grade gap, skill mastery, durable skills, interests.
F8 — Identity Quest (3-circle writing). 12 project types (who_am_i_poem, power_profile, my_hero_story, joy_map, define_family, family_tree, family_interview, our_story, community_map, community_hero, problem_solution, we_are_collective); rubric scoring + teacher/peer feedback + family share link; builds DurableSkillProgress.


10. Content authoring at scale [new / extends PDR]
The catalog needs items for ~2,000+ skills across K-12 — beyond hand-authoring. Build an authoring pipeline (the PDR's ExerciseGenerator is the seed of F-stage step 2):

Standards & catalog importer — parse the 2025 standards + the uploaded IXL plan PDFs into Standard2025 + seed ELASkill (~1,200 backbone).
AI item generation — given skill + activity type + grade + cultural tags, draft items (stem, options, distractor rationale, explanation, passage), with IRT difficulty estimates. Pre-generate and cache per skill (background job) rather than at test time.
Automated QA gates — readability/grade-band, answer-key validation, distractor plausibility, bias/sensitivity screen, duplicate detection.
Human review queue — curriculum lead approves/edits; status draft → in_review → published (the human-in-the-loop Rubric 02 needs).
Item analytics — post-launch p-value/point-biserial to retire weak items and recalibrate IRT params.

16. Improvement opportunities [from PDR]
Performance: pre-generate + cache LLM exercises per skill (background job); Supabase materialized views for heatmap aggregates; service worker + offline mode for low-bandwidth schools.
Better adaptive logic: full CAT with pre-calibrated AdaptiveItem bank; SM-2 spaced repetition; multi-dimensional IRT (θ per strand).
Richer writing: real-time AI writing coach (stream GPT-4o); automated rubric scoring via LLM evaluator; Whisper STT for oral projects.
Teacher UX: auto TeacherAlert via Supabase Edge Function triggers; export roster heatmap as PDF; bulk-assign interventions.
Engagement: opt-in class leaderboard; music/beat generation rewards; PWA push for streaks.
Compliance: FERPA data isolation; COPPA parental-consent flow (under-13); per-student data export (portability).


17. Success metrics
Primary gate = the six pilot rubrics (§2.1). Supporting metrics: standards coverage (% of 2025 leaves with ≥1 validated skill, target 100%/live grade), catalog depth (≥ N validated items per skill per difficulty band), placement accuracy vs external benchmark, median SmartScore gain/week, % on-track vs 1.5 RIT-pts/week, AI scoring agreement with human review, weekly return rate, crash-free %, teacher trust ≥ 4.0.


18. Open questions
Standards version (§5) — adopt 2025 K-12 ELA Standards as primary, or stay on GSE for pilot reporting? (Recommendation: adopt 2025 + crosswalk.)
SmartScore formula — replicate IXL behavior, or publish our own scoring curve (clearer for teachers, avoids mimicking proprietary IP)?
Catalog target — lock at the ~1,200 IXL-plan backbone, or extend to the PDR's ~2,000+ before launch?
Items per skill (N) — minimum item count per skill/band that gates a grade going live.
Migration cutover — big-bang from Base44, or run both in parallel during the K-5 phase?
Authoring ownership — who staffs the human-review queue, and at what throughput, to hit full K-12 coverage?
